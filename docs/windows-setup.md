# Запуск портала на ноутбуке с Windows

## Что поставить один раз

1. **Docker Desktop** с WSL 2 (установщик предложит включить WSL сам). Памяти ноутбуку нужно от 8 ГБ.
2. **Git for Windows.** Переводы строк настраивать не нужно: в репозитории есть `.gitattributes`, файлы останутся в формате Linux.
3. Склонировать репозиторий в любую папку, например `C:\welding-app`.

## Первый запуск

В PowerShell из папки репозитория:

```powershell
docker compose up -d --build
docker compose exec backend python manage.py loaddata fixtures/seed.json
docker compose exec backend python manage.py seed_demo
```

Первая сборка идёт 5–15 минут. Потом портал открывается на самом ноутбуке:

```
http://localhost:5173
```

Вход демонстрационного администратора: `admin` / `admin`. Остальные учётки из `seed_demo` — с паролем `demo`.

Демонстрационная телеметрия, если нужна:

```powershell
docker compose exec backend python manage.py seed_telemetry --with-card --live
```

После перезагрузки Windows контейнеры поднимаются сами, как только запустится Docker Desktop.

## Сеть с узлом

1. Воткнуть кабель от узла или от коммутатора, к которому он подключён.
2. Дать проводному адаптеру адрес из сети узла. Панель управления → «Сетевые подключения» (`ncpa.cpl`) → Ethernet → Свойства → IP версии 4:
   - IP-адрес: `192.168.1.10` (любой свободный в сети узла);
   - маска: `255.255.255.0`;
   - шлюз и DNS оставить пустыми, если интернет идёт по Wi-Fi.
3. При вопросе Windows о типе сети выбрать «Частная».
4. Проверить узел с ноутбука. Именно `curl.exe`: просто `curl` в PowerShell — это другая команда.

   ```powershell
   curl.exe http://192.168.1.50/api/state
   ```

5. Проверить, что узел виден из контейнера приёмника:

   ```powershell
   docker compose exec collector python -c "import urllib.request; print(urllib.request.urlopen('http://192.168.1.50/api/state', timeout=2).read())"
   ```

Если на ноутбуке включён VPN, на время работы с узлом его выключить: он может увести запросы в свою сеть.

## Включить опрос узла

Приёмник опрашивает узлы по HTTP, если в файле `.env` рядом с `docker-compose.yml` есть строка:

```
POLL_NODES=1
```

После правки `.env`:

```powershell
docker compose up -d collector
docker compose logs -f collector
```

В журнале должно появиться `опрос узла node-01: http://192.168.1.50/api/state`. Сеанс открывается, когда сварщик прикладывает карту. Закрывается, когда карту убрали или 10 минут не было дуги. Порог простоя меняется строкой `POLL_SESSION_IDLE_SECONDS=600` в том же `.env`.

Проверить всю цепочку без аппарата можно имитатором узла. Он работает внутри контейнера приёмника. Для этого в справочнике у аппарата указать адрес узла `127.0.0.1`, включить опрос и запустить:

```powershell
docker compose exec -d collector python node_stub.py
```

Сценарий имитатора длится около четырёх минут: карта, дуга полторы минуты, пауза, дуга с просадкой, простой, карту убрали. После проверки вернуть в справочнике настоящий адрес узла.

## Справочники в портале

- **Оборудование.** У аппарата указать узел: имя (например, `node-01`) и адрес (`192.168.1.50`).
- **Сварщики.** Каждому записать номер его RFID-карты. Без этого сеанс откроется без сварщика.

## Портал с других устройств

Наружу открыт только порт 5173. База, Redis, ClickHouse, MQTT и прямой порт бэкенда слушают только сам ноутбук.

Чтобы портал открывался с планшета или другого компьютера:

1. Создать рядом с `docker-compose.yml` файл `.env` с одной строкой — адресом ноутбука в этой сети:

   ```
   PORTAL_HOST=192.168.1.10
   ```

   Если там уже есть `POLL_NODES=1`, это вторая строка того же файла.

   В Блокноте при сохранении выбрать «Все файлы», иначе получится `.env.txt`.

2. Перезапустить бэкенд:

   ```powershell
   docker compose up -d backend
   ```

3. Разрешить входящие на порт 5173 в брандмауэре Windows (PowerShell от администратора):

   ```powershell
   New-NetFirewallRule -DisplayName "Портал сварки 5173" -Direction Inbound -Protocol TCP -LocalPort 5173 -Action Allow -Profile Private
   ```

4. С другого устройства открыть `http://192.168.1.10:5173`.

## Если что-то не так

| Что видно | Что сделать |
|---|---|
| Порт 5173 занят | Закрыть программу на этом порту или поменять левую часть в `docker-compose.yml`: `"5174:5173"` |
| С планшета ошибка 400 | Не задан или неверен `PORTAL_HOST` в `.env`, после правки — `docker compose up -d backend` |
| Узел не отвечает с ноутбука | Кабель, питание узла, адрес адаптера в той же подсети |
| Узел отвечает с ноутбука, но не из контейнера | Выключить VPN, перезапустить Docker Desktop |
| Портал пустой после переустановки | Повторить `loaddata` и `seed_demo` из «Первого запуска» |
