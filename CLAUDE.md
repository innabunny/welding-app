# Портал сварочного производства

Внутренняя система аэрокосмического предприятия. Регистрирует параметры
сварки с реальных аппаратов, привязывает их к сварщику и экземпляру
детали, сверяет с технологическими картами.

## Стек

```
backend/     Django 6 + DRF, PostgreSQL, ClickHouse (телеметрия),
             Channels + Redis + Daphne (WebSocket)
frontend/    React 19 + TypeScript (strict) + Tailwind 3 + TanStack Query
             + Zustand, recharts, lucide-react
collector/   приёмник MQTT: пишет события в Postgres, замеры в ClickHouse
```

Всё поднимается одним `docker compose up`. Бэкенд работает через `daphne`,
а не `runserver` — после правок нужен `docker compose restart backend`,
автоперезагрузки нет.

## Главное о предметной области

**Цепочка технологии:** деталь → операция → техкарта → шов.
Схема разделена на два слоя:

- `apps/technology` — «как надо»: `Part`, `Operation`, `SeamSpec`
- `apps/welding` — «как было»: `PartInstance`, `Weld`, `OperationRun`,
  `WeldPassRun`, `WeldingSession`, `ArcRun`, `Inspection`, `Deviation`

Один шов по чертежу варится за несколько операций: шов 13 мм — за две.
Поэтому заключения контроля и отклонения вешаются на операцию
(`OperationRun`), а не на шов — иначе непонятно, после каких проходов
возник дефект.

**Корень телеметрии — `WeldingSession`,** он цепляется к аппарату
и сварщику, а НЕ к шву. Отработка режимов и прихватка оснастки — это
сварка, которой никакого шва по чертежу не соответствует. Режимы:
«по техпроцессу», «отработка», «прихватка».

**Узел телеметрии** меряет только ток и напряжение. Всё остальное
считается из них: время дуги по порогу 5 А, остановки по промежуткам
между участками дуги, скорость по длине шва и времени, расход газа
и проволоки по норме из карты. Расход — это ОЦЕНКА, не измерение.

**Сопоставление проходов недостоверно.** Границы проходов система
определяет расчётом по накопленному времени дуги. Поэтому у `WeldPassRun`
есть `match_source`: вручную / датчик / ток / пауза / расчёт. Это надо
показывать пользователю — он должен видеть, насколько данным можно верить.

**Снимки значений.** Поля вида `welder_name`, `author_name`,
`inspector_name` — это снимки на момент события. Человек может уволиться
или сменить фамилию, а документ должен читаться годы спустя. Не заменять
их на запросы к связанной записи.

## Чего НЕЛЬЗЯ делать на фронте

**Не считать то, что считает бэкенд.** Кз, фонд времени, раскладку
времени, расход материалов, отклонения — всё это приходит готовым
из API. Два расчёта однажды разойдутся, и никто не поймёт, какой верный.

**Не подключаться к MQTT из браузера.** Живые данные идут через
WebSocket портала: браузер не должен знать про брокер, и авторизация
портала не должна обходиться.

**Не обращаться к узлу телеметрии напрямую по его IP.** Данные идут
через приёмник и базу.

**Не использовать браузерные хранилища для данных.** `localStorage`
годится только для мелких удобств вроде выбранной вкладки.

## Терминология — писать именно так

| Правильно | Не писать |
|---|---|
| Кз, коэффициент загрузки | «загрузка, %», «утилизация» |
| фонд времени | «план», «доступное время» |
| время горения дуги | «основное время», «время работы» |
| режим ожидания | «вспомогательное время», «idle» |
| простой | «downtime» |
| нет данных | «неизвестно», «offline» |
| выполненные сварочные работы | «выпуск», «производительность» |
| суммарная длина швов | «длина швов», «метраж» |
| сборочная единица | «деталь», «изделие» |
| образец-свидетель | «образец», «свидетель» |

Фонд времени — всегда полная смена по графику, независимо от времени
суток. Прошедшая и оставшаяся части показываются отдельно.

## График смен

Понедельник–четверг 07:15–16:30, пятница 07:15–15:15, обед 11:30–12:30.
Переработка 15 минут четыре дня — чтобы пятница была на час короче;
за неделю ровно 40 часов. Пятничный фонд на час меньше, поэтому Кз
по дням показывать в процентах, а не в часах — иначе пятница выглядит
как всплеск производительности.

Смены и производственный календарь — `apps/shifts`. Праздники правятся
в админке.

## Отклонения и решения

Отклонение фиксируется автоматически, но судьбу шва решает человек.
Это главная ценность системы: сейчас такие решения принимают устно.

Два разных списка для двух разных людей:

- **отклонения режима** (ток, напряжение, скорость) → очередь технолога,
  решения: допущено / на контроль / на переварку
- **нарушения порядка** (`без_карты`, `без_допуска`) → мастеру,
  решение: разобрано

Отклонение — это серьёзно: шов может уйти на переварку, а деталь стоит
дорого. Визуально не оформлять как милое предупреждение.
